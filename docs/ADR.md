# ADR — 결정과 버린 대안

포맷: 결정 / 근거 / **버린 대안과 이유** / 되돌릴 조건.
이 파일이 이 레포의 차별점이다. 채택안만 적지 말고 **진 것도 적는다.**

## ADR-001. 기존 저장소를 전환하지 않고 새 저장소로 재출범 (2026-09-05)
- **결정**: 이전 private 저장소를 public 전환하지 않고, 스크럽본으로 fresh init 한 새 저장소를 공개한다.
- **근거**: 리스크 검수 결과 현재 트리 12곳 + git 히스토리 + CI 실행 로그 + 스크린샷 메타데이터에 조직 식별정보가 분산돼 있었다. 히스토리 재작성(filter-repo + force-push)은 누락 리스크가 남고, CI 실행 로그는 어차피 별도 삭제가 필요했다.
- **버린 대안**: (a) `git filter-repo`로 히스토리 세탁 후 전환 — 커밋 8개를 보존할 수 있으나 누락 시 복구 불가. (b) 그대로 공개 — 불가.
- **되돌릴 조건**: 없음(비가역).

## ADR-002. 벡터스토어를 하나로 고르지 않고 둘 다 구현 (2026-09-05)
- **결정**: `VectorStore` 인터페이스 뒤에 **pgvector**와 **Qdrant** 두 구현을 두고, 동일 평가셋으로 hit@k·MRR·p95 지연을 측정해 운영 기본값을 정한다.
- **근거**: 선택의 근거를 수치로 제시하는 것 자체가 포트폴리오 재료다. 임베딩 모델 벤치마크 하네스를 그대로 재사용하므로 한계비용이 작다.
- **버린 대안**: pgvector 단일(스택은 가장 단순하나 "왜 그것인가"에 답이 없음) / Qdrant 단일(컨테이너가 늘고 PostgreSQL 채택 서사와 분리됨).
- **되돌릴 조건**: 벤치마크 격차가 유의미하지 않고 유지비용만 늘면 승자 하나만 남기고 패자 구현은 `docs/BENCHMARKS.md`에 기록만 남긴다.

## ADR-003. RAG 원본 SOP를 가상 문서로 자체 집필 (2026-09-05)
- **결정**: 기존 원본 PDF(제3자 저작, 문서 메타데이터에 작성 조직이 남아 있음)를 폐기하고, 공개 표준을 참고해 **가상 데이터센터 SOP**를 새로 집필해 공개한다. 생성 프롬프트와 참고 출처도 함께 공개한다.
- **근거**: 저작권 청정이 확정되고, 데이터 생성 과정 자체가 검증 가능한 산출물이 된다.
- **버린 대안**: 공개 표준문서(NIST·ITIL 등)를 원본으로 그대로 적재 — 라이선스 재확인 부담이 있고 데이터센터 설비 도메인과 어긋난다.
- **되돌릴 조건**: 없음.

## ADR-004. (템플릿) 임베딩 모델 선정
- **결정**: 미정 — `make eval` 결과로 확정한다.
- **후보**: BGE-m3 / multilingual-e5-large / KURE-v1 / Qwen3-Embedding-0.6B
- **판정 기준**: 한국어 SOP 골드셋 30건의 hit@5·MRR, 임베딩 지연(p95), 모델 크기.
